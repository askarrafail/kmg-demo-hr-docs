# Тестовые задачи для Cowork
### Проект «Инструкции по ИТ-системам»

Готовые промпты для проверки возможностей Cowork на реальных файлах проекта.
Каждый промпт копируется целиком в новую сессию Cowork внутри проекта — тогда файлы проекта подтягиваются автоматически.

**Легенда:**
🟢 базовый уровень · 🟡 средний · 🔴 продвинутый

---

## 🟢 1. Аналитика по табличным данным

**Что проверяем:** реальные вычисления по вашим xlsx (не «на глаз»), генерация файла на выходе.
**Время:** ~5 минут.

```
Возьми «Журнал обращений в поддержку 2 кв 2025.xlsx» и «Отчёт по SLA и доступности систем.xlsx».
Посчитай:
1) топ-10 тем обращений по количеству и их долю в общем потоке;
2) среднее и медианное время решения по каждой теме;
3) по каким темам и системам чаще всего нарушался SLA.
Собери результат в один xlsx: лист «Сводка» с ключевыми цифрами и диаграммой,
лист «Детализация» с полной таблицей.
```

**Ожидаемый результат:** готовый .xlsx файл с расчётами и графиком.
**На что смотреть:** цифры должны сходиться с исходником — проверьте 2-3 строки вручную.

---

## 🟡 2. Поиск пробелов в документации

**Что проверяем:** чтение PDF + сведение двух разнородных источников + практический вывод.
**Время:** ~10 минут.

```
Сопоставь темы обращений из «Журнал обращений в поддержку 2 кв 2025.xlsx»
с содержанием «БЗИТ003 База знаний службы поддержки.pdf».
Найди темы, по которым обращений много, а инструкции в базе знаний нет либо она неполная.
Дай таблицу: тема — кол-во обращений — есть ли инструкция — что делать (создать/обновить/ок) — приоритет (1-3).
Отсортируй по приоритету. В конце — короткий вывод: какие 5 инструкций дадут максимальное
снижение нагрузки на поддержку.
```

**Ожидаемый результат:** приоритизированный бэклог документации.
**Почему это лучший демо-кейс:** результат сразу применим в работе, а не «игрушечный».

---

## 🟡 3. Пакетная генерация инструкций по шаблону

**Что проверяем:** соблюдение формата проекта + выдача нескольких документов за один прогон.
**Время:** ~10 минут.

```
Из «РГИТ018 Инструкция по ЭДО.pdf» сделай 3 отдельные короткие инструкции
по самым частым пользовательским сценариям.
Формат — строго по шаблону проекта: название, назначение и целевая аудитория,
предпосылки, пошаговый алгоритм, FAQ, к кому обращаться.
Каждую инструкцию отдай отдельным .docx файлом.
```

**Ожидаемый результат:** 3 файла .docx.
**На что смотреть:** выдержан ли шаблон, выделены ли элементы интерфейса, есть ли блок FAQ.

**Вариант посложнее:** то же самое, но из «РПИТ014 Руководство пользователя САП.pdf» — документ объёмнее, видно, как модель работает с большим контекстом.

---

## 🟢 4. Сырьё → рабочий документ

**Что проверяем:** синтез из разных типов документов (инцидент + служебка + регламент).
**Время:** ~5 минут.

```
На основе «Разбор инцидента 17 мая 2025.md», «СЗ-2025-04128 Служебная записка о сбоях
при проведении актов.docx» и «Регламент дежурной смены ИТ.md»
сделай памятку для дежурного инженера: что делать при сбоях проведения актов в SAP.
Одна страница, пошагово, с отдельным блоком «когда эскалировать и кому».
Отдай .md файлом.
```

**Ожидаемый результат:** памятка на одну страницу.

---

## 🔴 5. Живой каталог инструкций (артефакт)

**Что проверяем:** публикация результата как веб-страницы со ссылкой для команды.
**Время:** ~15 минут.

```
Собери HTML-страницу «Каталог ИТ-инструкций»:
карточки инструкций, сгруппированные по системам (SAP, ЭДО, корпоративный портал, удалённый доступ),
поиск по названию, фильтры по системе и по аудитории (пользователь / администратор / дежурный).
Данные возьми из документов проекта.
Опубликуй как артефакт и дай ссылку.
```

**Ожидаемый результат:** ссылка на страницу, которую можно открыть с любого устройства и обновлять из чата.

---

## 🟡 6. Чек-лист обновления SAP → рабочий план

**Что проверяем:** превращение чек-листа в управляемый план с ролями и сроками.
**Время:** ~7 минут.

```
Возьми «Чек-лист подготовки к обновлению SAP до SP24.md» и «Протокол совещания ПС-ИТ-2025-041.docx».
Сделай план работ: этап — задача — ответственная роль — срок относительно даты X —
критерий готовности — риск при невыполнении.
Отдельно вынеси пункты, по которым в исходниках нет ответственного или срока.
Формат — xlsx.
```

**На что смотреть:** нашла ли модель пробелы в исходных документах (это самая полезная часть).

---

## 🔴 7. Инструкция со скриншотами (Claude in Chrome)

**Что проверяем:** автоматический сбор скриншотов интерфейса — самая трудоёмкая часть техписа.
**Время:** ~15 минут. Требует расширения Claude in Chrome.

```
Открой корпоративный портал, пройди сценарий [название сценария] шаг за шагом,
делай скриншот на каждом шаге и подсвечивай нужную кнопку.
Собери инструкцию по шаблону проекта со вставленными скриншотами. Отдай .docx.
```

⚠️ **Важно:** работает только на системах, доступных из вашего браузера, и требует выданных расширению прав на конкретный домен.

---

## 🔴 8. Регулярная задача по расписанию

**Что проверяем:** автономную работу без вашего участия.
**Время:** настройка ~2 минуты.

```
Настрой задачу: каждый понедельник в 09:00 брать свежий журнал обращений,
находить темы, по которым за прошлую неделю был всплеск обращений,
сверять с базой знаний и присылать список: что нужно создать или обновить в документации.
```

💡 **Совет:** для демонстрации на обучении задачу можно запустить вручную — не нужно ждать понедельника.

---

## Порядок для демонстрации

Если показываете Cowork аудитории, лучший сценарий — связная история, а не набор фич:

| Шаг | Задача | Что видит зритель |
|-----|--------|-------------------|
| 1 | Задача №1 | «Он реально считает мои данные» |
| 2 | Задача №2 | «Он делает вывод, а не пересказ» |
| 3 | Задача №3 | «Он отдаёт готовый документ по нашему шаблону» |
| 4 | Задача №5 | «Результатом можно поделиться по ссылке» |

Итого ~40 минут на полный цикл «данные → вывод → документ → публикация».

---

## Чек-лист проверки качества

После каждой задачи проверьте:

- [ ] Цифры сходятся с исходником (выборочно 2-3 значения)
- [ ] Соблюдён шаблон инструкции проекта
- [ ] Нет выдуманных названий кнопок и разделов, которых нет в исходных PDF
- [ ] Указаны источники, откуда взяты данные
- [ ] Файл открывается и корректно форматирован

⚠️ **Важно:** модель может уточнять названия элементов интерфейса, которых нет в исходниках. Для пользовательских инструкций это критично — сверяйте с реальной системой перед публикацией.
